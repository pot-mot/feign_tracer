### 测试暴露并修掉的缺陷
1. `java.ts` / `groovy.ts`：`textOf()` 不保留空格，`import static a.b.C.d` 被解析成
   `statica.b.C.d` 且 `static: false` → 静态导入永远解析不到宿主类型。
2. `kotlin.ts`：`import a.b.Tools as Toolkit` 被粘成 `a.b.ToolsasToolkit`，别名丢失
   → 改为从 `importAlias` 子树读取（文本无法消歧，类名本身可能以 `as` 结尾）。
3. `callscan.ts`：链式调用 `factory.build(id).commit()` 的接收者被截成 `id)` → 先整体
   跳过配对的 `()`/`[]` 再回溯边界，现在得到 `factory.build(id)`。
4. `common.ts`：全限定注解 `@org.springframework.stereotype.Service` 不归约为简单名，
   导致 `kindOf`/端点映射表全部失配（gradle-shop 的 DemoService 被当成 component）
   → `parseAnnotation` 统一归约，`raw` 保留原文。
5. `groovy.ts`：构造器 `isConstructor` 恒为 false（无返回类型 + 与类同名未识别）
   → `new Foo(...)` 永远解析不到目标。
